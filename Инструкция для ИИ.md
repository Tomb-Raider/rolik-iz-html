# Ролик из HTML. Инструкция для ИИ

Для человека. В чате (GigaChat, ChatGPT, Claude) вставьте этот файл целиком первым сообщением, вторым сообщением заполненный «Шаблон промта». Если ИИ работает агентом в папке (Claude Code, Codex, Cursor), положите копию файла рядом с плеером под именем `CLAUDE.md` или `AGENTS.md`

---

## Задача

Ты пишешь сцены для короткого ролика. Ролик это список сцен с длительностями. Плеер «Ролик из HTML» показывает сцены подряд в кадре 1920×1080 или вертикальном 1080×1920, у него есть таймлайн, перемотка на любую секунду, повтор сцены, замедление и режим записи. Плеер уже готов. Твоя работа только код сцен по договору ниже. Плеер и страницу целиком не пиши.

## Как ответить

- Один блок кода на JavaScript. В нём вызовы `reel(...)` и `scene(...)`, при необходимости свои функции и константы
- Без `<html>`, `<script>`, `<style>`, без внешних библиотек, без загрузки чего-либо из интернета, без картинок и видео по ссылкам
- Если просят весь ролик, сначала `reel(...)`, потом все сцены по порядку
- Если просят поправить одну сцену, пришли только её, с тем же `name`. Плеер заменит сцену с таким названием и оставит остальные
- Сцену присылай всегда целиком. Без «остальное без изменений» и без многоточий вместо кода
- Если весь ролик не помещается в один ответ, присылай сцены целиком по порядку и напиши, что продолжение будет в следующем сообщении. Сцену посередине не обрывай
- Если человек прислал текст красной плашки из плеера, найди по нему ошибку и пришли исправленную сцену целиком
- Если просят новую сцену, дай ей новое `name`. Плеер поставит её в конец
- До блока кода можно одной-двумя фразами сказать, что сделано. Объяснения после кода не нужны

## Договор сцены

```js
scene({
  name: 'Фразы',             // название, видно на таймлайне. Внутри ролика уникальное
  dur: 3.6,                   // длительность в секундах
  note: 'что в сцене',        // по желанию: одной фразой, что происходит. Видно в плеере
  html: `<div class="line">...</div>`,  // разметка сцены, ставится один раз
  css: `.line { ... }`,       // стили. Действуют только внутри этой сцены, корень сцены это :scope
  draw({ t, p, dur, el, $, $$, w, h }) {
    // рисует кадр по времени t
  },
})
```

- `t` время от начала сцены в секундах, от 0 до `dur`. `p` это `t / dur`, от 0 до 1
- `el` корневой элемент сцены. `$('.x')` находит первый элемент внутри сцены, `$$('.x')` все, массивом
- `w`, `h` размер кадра в пикселях (1920 и 1080)
- Корень сцены уже растянут на весь кадр (`position: absolute; inset: 0`). Фон кадра и цвет текста задаёт ролик
- Сцена без `html` и `draw` показывается заглушкой с названием и `note`. Так можно сначала собрать раскадровку из одних названий и длительностей, а потом наполнять сцены по одной

Сцены идут встык, жёсткой склейкой. Если нужен плавный переход, сделай так, чтобы последний кадр сцены совпадал с первым кадром следующей.

Длину сцены человек может поменять на таймлайне плеера, потянув край сцены. Тогда плеер растягивает или сжимает время сцены: `t` в `draw` всё равно идёт от 0 до `dur`, код сцены менять не нужно. Такие длины лежат в отдельной части кода `//// длительности из плеера` как `reel({ grid, lengths: { 'Название': 4 } })`. Не меняй и не удаляй эту часть. Если человек словами просит другую длину сцены, меняй `dur` в самой сцене: длина из плеера для неё тогда сбросится.

## Главное правило. Кадр зависит только от t

Плеер может встать на любую секунду, отмотать назад, шагнуть на кадр, крутить одну сцену по кругу. Поэтому `draw` по одному `t` выставляет всё, что движется, каждый раз заново, целиком. Никакой памяти между кадрами.

Нельзя:
- `setTimeout`, `setInterval`, `requestAnimationFrame`, `Date`, `performance.now()`
- `Math.random()`. Для случайности `R.rand(номер)`, оно одинаковое при каждом вызове
- CSS `animation`, `transition`, `@keyframes`, а также `el.animate()`
- переменные, которые копят состояние между вызовами `draw` (счётчики, «прошлый кадр», флаги «уже показали»)
- добавлять элементы в `draw` через `append`. Если состав элементов меняется от времени, пересобирай его целиком через `innerHTML` или заранее положи всё в `html` и прячь лишнее

Можно:
- менять `style`, `textContent`, `innerHTML`, классы, атрибуты SVG
- считать от `t` любые формулы
- мерить размеры (`offsetWidth`) прямо в `draw`

Проверка. Вызови мысленно `draw` с `t = 1.5`, потом с `t = 0.2`, потом снова с `t = 1.5`. Первый и третий кадр должны совпасть до пикселя.

Важная мелочь. Если у потомка стоит `visibility: visible`, он виден даже внутри родителя с `visibility: hidden`. Целые блоки прячь через `style.display = 'none'`.

Ещё одна. Двигай и масштабируй только через `transform`. Отдельные CSS-свойства `translate` и `scale` в сценах не ставь: ими плеер показывает поверх кадра правки человека.

## Кадр

Кадр по умолчанию 1920×1080 px (16:9), плеер сам масштабирует его под окно. Все размеры пиши в px для этого кадра. Крупный текст для ролика начинается от 120 px, подписи от 48 px. Отступы от краёв кадра не меньше 96 px. Они касаются всего, что нужно прочитать или разглядеть: текста, графики, рамок. За край может уходить только фон и то, что нарочно уезжает из кадра.

Вертикальный кадр 1080×1920 px (9:16) для Telegram и сторис задаётся в `reel`: `width: 1080, height: 1920`. Тогда `w` и `h` в `draw` равны 1080 и 1920. Ширина кадра почти вдвое меньше, поэтому фразы короче, крупный текст около 100-150 px, отступы те же 96 px.

## Бренд. Цвета и шрифт

Все цвета и шрифт задаются переменными в `reel({ css })`. В сценах пиши `var(--fg)`, `var(--accent)` и свои переменные, а не hex. Так бренд меняется в одном месте.

```js
reel({
  title: 'Название ролика',
  fps: 24,                  // шаг по кадру в плеере, клавиши ← →
  // width: 1080, height: 1920,   // вертикальный кадр 9:16. Без этой строки кадр 1920×1080
  css: `
    :root {
      --bg: #0B0D10;        /* фон кадра */
      --fg: #FFFFFF;        /* основной текст */
      --accent: #3D7CFF;    /* акцент */
      --c1: #3D7CFF; --c2: #22C1A6; --c3: #FFC53D;   /* дополнительные цвета бренда */
      --font: "SB Sans Display", system-ui, sans-serif;
    }
  `,
})
```

Шрифт. Если шрифт установлен на компьютере, достаточно вписать его название первым в `--font`. Последним всегда оставляй запасной `system-ui, sans-serif`. Если шрифт лежит файлом рядом с роликом, подключи его в том же `css`:

```css
@font-face { font-family: "Brand"; src: url("fonts/Brand-Bold.woff2"); font-weight: 700; }
```

Начертание задавай `font-weight` (400, 500, 600, 700), а не отдельным именем шрифта.

## Помощники R

Плеер даёт объект `R`. Пользуйся им вместо своих копий.

- `R.prog(t, start, dur)` прогресс отрезка от 0 до 1: до `start` 0, после `start + dur` 1
- `R.mix(a, b, k)` значение между `a` и `b` по доле `k`
- `R.clamp(x, a, b)` ограничить `x` между `a` и `b` (по умолчанию 0 и 1)
- `R.ease.linear`, `R.ease.in`, `R.ease.out`, `R.ease.inOut`, `R.ease.outCubic`, `R.ease.inOutCubic` кривые плавности
- `R.ease.inOutQuint` кривая `cubic-bezier(0.83, 0, 0.17, 1)`, дописывание слова в пресете ниже
- `R.ease.enter` кривая `cubic-bezier(0.094, 0.656, 0.383, 1)`, въезд первой строки в пресете ниже
- `R.bezier(x1, y1, x2, y2)` своя кривая как в CSS
- `R.keys(t, [[0, 0], [0.4, 1, R.ease.out], [1.2, 1]])` значение по ключевым точкам `[время, значение, кривая]`. Значение числом или массивом чисел
- `R.snap(t, 24)` время на сетке 24 кадра в секунду, движение становится рубленым, как в кино
- `R.rand(n)` случайное число от 0 до 1, одно и то же для одного `n`

Типичная строка в `draw`:

```js
const k = R.ease.out(R.prog(t, 0.3, 0.5))    // с 0,3 с по 0,8 с плавно от 0 до 1
$('.title').style.transform = `translateX(${R.mix(-200, 0, k)}px)`
```

## Пресет «Короткие фразы как в рекламе Apple»

Используй, когда просят «как в рекламе Apple», «кинетический текст», «короткие фразы». Числа сняты покадровыми замерами с референса, не округляй их и не «улучшай»: расхождение в 30-50 мс убивает эффект.

Как выглядит
- Тёмный фон, белый текст, начертание Bold (700), кегль 154 px (14,3 % высоты кадра), строка по центру кадра по обеим осям
- Строка из двух частей. Сначала одно слово, потом к нему дописывается второе
- Время в `draw` округляй через `R.snap(t, 24)`. Так движение идёт рублеными кадрами 24 к/с (кадр 41,667 мс), как в референсе

Тайминги
- Строка живёт 1,2 с: первое слово одно 430 мс, дописывание 250 мс, полная строка держится до склейки. Если задан темп музыки, жизнь строки (`life`) можно подогнать под доли, например 1 с, 1,5 с или 2 с при 120 ударах в минуту. Остальные числа не меняй
- Дописывание. Ширина второй части вместе с пробелом растёт от 0 до 100 % за 250 мс по кривой `R.ease.inOutQuint`. Строка стоит по центру, поэтому первое слово само уезжает влево на половину прироста. Слова руками не двигай
- Само второе слово появляется на 167 мс от начала дописывания, мгновенно, за один кадр, без проявления. В этот кадр слова выглядят слипшимися, так и надо
- Непрерывный отъезд. Всю жизнь строки масштаб линейно уменьшается на 15 % в секунду. Только `scale`, без сдвига. Если строка живёт дольше 1,2 с, отъезд медленнее: за всю жизнь строка уменьшается не больше чем на 18 %, как за 1,2 с. Так длинная строка не мельчает
- Перед склейкой два последних кадра строка сжимается сильнее: дополнительно на 1 % и на 3 %
- Склейка между строками жёсткая: кадр старой строки, следующий кадр новой. Новая строка появляется сразу в центре с ударом масштаба +5 %, который гаснет за 60 мс по `R.ease.out`
- Первая строка сцены въезжает слева: сдвиг от минус 15 % ширины кадра до 0 за 417 мс по `R.ease.enter`. Масштаб при въезде не меняется
- Въезд слева нужен, когда текст приходит после сцены другого вида. Если перед сценой с фразами уже стояла строка текста по центру (например, тоже сцена по пресету), ставь `enter: false`: первая строка войдёт жёсткой склейкой с ударом +5 %, как остальные

Готовый код пресета. Меняй только фразы и название, механику не трогай:

```js
const FPS = 24, F = 1 / FPS

// Одна строка пресета в момент lt от её начала. Ею же собирай свои сцены, где рядом с фразой своя графика
function phraseAt(line, lt, { life = 1.2, first = 0.43, punch = true, enter = false, w = 1920 } = {}) {
  const add = line.lastElementChild, word = add.firstElementChild
  add.style.width = word.offsetWidth * R.ease.inOutQuint(R.prog(lt, first, 0.25)) + 'px'  // дописывание 250 мс
  add.style.overflow = lt >= first + 0.25 ? 'visible' : 'hidden'     // дописали, дальше ничего не обрезаем
  word.style.visibility = lt >= first + 0.167 ? 'visible' : 'hidden'  // слово возникает за 83 мс до остановки
  let s = 1 - 0.15 * Math.min(1, 1.2 / life) * lt           // отъезд 15 % в секунду, за жизнь строки не больше 18 %
  if (lt >= life - 2 * F) s -= lt >= life - F ? 0.03 : 0.01 // разгон перед склейкой
  if (punch) s *= 1 + 0.05 * (1 - R.ease.out(R.prog(lt, 0, 0.06)))  // удар +5 % на склейке
  const x = enter ? -0.15 * w * (1 - R.ease.enter(R.prog(lt, 0, 0.417))) : 0  // въезд слева
  line.style.transform = `translateX(${x}px) scale(${s})`
}

const PHRASE_CSS = `
  .line { position: absolute; inset: 0; display: flex; align-items: center; justify-content: center;
          font-weight: 700; font-size: 154px; line-height: 1.25; letter-spacing: -0.015em; white-space: nowrap; }
  .add { display: flex; justify-content: flex-end; overflow: hidden; }
  .add > span { flex: none; }
`

function phrases(name, lines, { life = 1.2, first = 0.43, enter = true } = {}) {
  return {
    name,
    dur: lines.length * life,
    note: lines.map(l => l.join(' ')).join(' / '),
    html: lines.map(([a, b]) =>
      `<div class="line"><span>${a}</span><span class="add"><span>&nbsp;${b}</span></span></div>`).join(''),
    css: PHRASE_CSS,
    draw({ t, $$, w }) {
      t = R.snap(t, FPS)                                          // рубленая сетка 24 кадра в секунду
      const k = Math.min(lines.length - 1, Math.floor(t / life))  // какая строка сейчас
      $$('.line').forEach((line, i) => {
        line.style.display = i === k ? '' : 'none'               // склейка: кадр старой строки, следующий кадр новой
        if (i === k) phraseAt(line, t - k * life, { life, first, punch: k > 0 || !enter, enter: k === 0 && enter, w })
      })
    }
  }
}

scene(phrases('Фразы', [
  ['Текст', 'настоящий.'],
  ['Цвет', 'из бренда.'],
  ['Правка', 'за минуту.'],
]))
```

Пример с параметрами: `phrases('Фразы', [...], { life: 1, enter: false })`.

Если в строке одно слово, второй частью сделай пустую строку `''`.

Если фраза не влезает в ширину кадра с отступами 96 px, уменьши `font-size` у этой сцены, но не меньше 120 px. Механика пресета при этом та же:

```js
const anyAI = phrases('Любой ИИ', [['Любой ИИ,', 'который пишет код.']], { life: 2 })
anyAI.css += `.line { font-size: 120px; }`
scene(anyAI)
```

Если и при 120 px фраза не влезает, раздели её по смыслу на две строки пресета, у каждой своё дописывание, и скажи об этом человеку одной фразой. Слова не выкидывай и не меняй.

Свои сцены в ролике с пресетом. Держи тот же характер: склейки жёсткие, текст без проявлений, при желании тот же отъезд 15 % в секунду и удар +5 % в первые 60 мс сцены. Цифры, точки и другую графику можно двигать свободнее, но без запретов из списка ниже.

Если в сцене фраза по пресету и рядом своя графика, не пиши механику строки заново. Возьми ту же разметку строки, стили `PHRASE_CSS` и `phraseAt` в `draw`:

```js
scene({
  name: 'Таймлайн',
  dur: 3,
  html: `<div class="line"><span>Таймлайн</span><span class="add"><span>&nbsp;по сценам.</span></span></div>
         <div class="bar"></div>`,
  css: PHRASE_CSS + `
    .line { bottom: 160px; }   /* фраза на 80 px выше центра, под ней место для полоски */
    .bar { position: absolute; left: 320px; top: 620px; height: 64px; border-radius: 12px; background: var(--accent); }
  `,
  draw({ t, $ }) {
    t = R.snap(t, FPS)
    phraseAt($('.line'), t, { life: 3 })                              // строка живёт всю сцену
    $('.bar').style.width = 1280 * R.ease.inOutQuint(R.prog(t, 0.75, 0.25)) + 'px'
  }
})
```

Пока второе слово дописывается, у `.add` стоит `overflow: hidden`: всё, что выходит за края слова, обрезается. Рамку, подчёркивание и другую графику вокруг второго слова показывай после дописывания, не раньше `first + 0,25` с от начала строки.

## Чего не делать в движении

Эти запреты проверены по замерам референса. Они действуют для пресета и по умолчанию для всего ролика, если в задании не сказано иное.

- Никаких проявлений и растворений (fade). Ни на появлении, ни на склейке, ни на уходе
- Никакого размытия, в том числе размытия в движении (blur, motion blur)
- Никакого вертикального движения текста. Текст двигается только по горизонтали и масштабом
- Никаких поворотов, перспективы и 3D
- Никаких пружин с перелётом (overshoot). Единственный перелёт это удар +5 % на склейке
- Не заменяй жёсткую склейку плавным переходом
- Не придумывай свои цвета и шрифты, бери из переменных бренда
- Без градиентов, теней и обводок, если их нет в задании

## Один пик

Если в задании не сказано иное, у ролика один пик ближе к концу. Это одна сцена сильнее остальных: крупнее, с ударом или держится дольше. Сцены до неё спокойнее и короче. Когда все сцены одинаково яркие, глазу не за что зацепиться.

## Другие стили и приёмы

Человек может прислать стиль или приём из пакета («Плавный», «Пролёт», «Кольцо прогресса», «Шторка» и другие) с правилами и готовым кодом. Держись его правил и чисел так же строго, как пресета Apple, меняй только текст, числа, цвета и длительность. Запреты из раздела «Чего не делать в движении» тогда действуют, только если стиль не говорит иначе.

## Правки из плеера

Человек может поправить ролик прямо в плеере: на паузе подвинуть объект, поменять ширину блока с текстом или размер фигуры, исправить текст, оставить замечание. Код от этого не меняется. Плеер показывает правки поверх кадра и присылает их в запросе из «Для ИИ» блоком `ПРАВКИ ИЗ ПЛЕЕРА`:

```
ПРАВКИ ИЗ ПЛЕЕРА · записей: 4
кадр 1920 × 1080, числа в пикселях кадра, t в секундах от начала сцены, как в её draw

═══ «Титул» · 0-2 с ролика

[1] t = 0,50 · «Ролик из HTML» · div.title > span.txt
- Ролик из HTML
+ Ролик за минуту
  этот текст ставит draw, поменяй строку в коде сцены

═══ «Фразы» · 2-5,6 с ролика

[2] t = 0,30 · «Текст настоящий.» · div.line:nth-child(1)
  сдвиг: вверх на 200 · начало движения как было, с этого момента на новом месте
  выровнено: центр по горизонтали по центру кадра

[3] t = 2,00 · «Ваш шрифт и ваши цвета» · p.cap
  ширина: 735 → 498, строки переносятся, размер букв тот же

[4] t = 2,00 · <div.row> · div.row
  размер: 1000 × 120 → 826 × 99
! точки пусть встают быстрее
```

Как читать:
- `═══ «Сцена»` название сцены. Правь эти сцены, остальные не трогай
- `t` момент правки в коде сцены, в тех же секундах, что `t` в `draw`
- После `t` подпись элемента (его текст или тег с классом) и путь от корня сцены: `div.line:nth-child(1)` это первый `.line` в корне, `div.title > span.txt` это `.txt` внутри `.title`
- `- было` и `+ стало` текст. `&nbsp;` неразрывный пробел. «Этот текст ставит draw» значит, что строка лежит в коде `draw` или в данных, из которых он её берёт, а не в `html`
- `сдвиг` в пикселях кадра, вправо и вниз положительно. Перенеси его так, как устроена сцена: поправь `left`, `top`, отступ или координату, которую считает `draw`
- Если объект в сцене движется, после сдвига сказано, как сдвиг ложится на движение:
  - «весь путь движения»: прибавь сдвиг ко всему пути, на каждом кадре
  - «начало движения как было, с этого момента на новом месте»: в начале сцены объект там же, где был, к моменту `t` плавно приходит на новое место и дальше движется от него. Например, прибавь к координате `dy * R.ease.inOut(R.prog(t, 0, t0))`, где `t0` момент правки
  - «только в этот момент, начало и конец движения как были»: в момент `t` объект на новом месте, к началу и к концу сцены плавно возвращается на старый путь. Например, прибавь `R.keys(t, [[0, 0], [t0, dy, R.ease.inOut], [dur, 0, R.ease.inOut]])`
- Сдвиг из плеера важнее запретов пресета и раздела «Чего не делать в движении»: человек сам поставил объект туда. Если сцена собрана функцией пресета, например `phrases`, механику пресета не меняй, а добавь сдвиг поверх её `draw`:

```js
const title = phrases('Титул', [['Ролик', 'из HTML']], { life: 2 })
const drawTitle = title.draw
title.draw = a => {
  drawTitle(a)
  const line = a.$('.line'), dy = -73 * R.ease.inOut(R.prog(a.t, 0, 1))   // начало как было, к 1 с вверх на 73
  line.style.transform = `translateY(${dy}px) ${line.style.transform}`
}
scene(title)
```

- `ширина: 735 → 498` у блока с текстом: сделай блок такой ширины, строки переносятся, размер шрифта не меняй. Число это ширина видимого текста. Если блок растянут во всю ширину кадра, поставь ему эту ширину и выровняй так же, как стоял текст (по центру `margin: 0 auto`)
- `размер: 1000 × 120 → 826 × 99` у фото или фигуры без текста: она меньше или больше целиком, пропорции те же. Центр остаётся на месте, как в плеере. Поменяй её размеры и в той же доле размеры того, что внутри: зазоры, скругления, толщины. `scale` в `transform` бери, только если иначе никак
- Ширина и размер одни на всю сцену, от движения не зависят
- `выровнено` важнее чисел. «Центр по горизонтали по центру кадра» значит, что центр объекта ровно на вертикальной оси кадра (x = 960 при ширине 1920), а по высоте объект стоит, как сказано в сдвиге. «Середина по вертикали по середине кадра» то же по высоте. «Левый край по полю 96 px слева» значит ровно на 96 px от края
- `!` замечание словами. Сделай, что просит. Замечание висит на том объекте, по которому щёлкнули, а говорить может о соседнем, смотри по смыслу. Его плеер сам не убирает, человек удалит его, когда проверит
- «в кадре не нашёлся» значит, что сцену или элемент уже поменяли. Найди по подписи

Плеер сам убирает правку из списка, когда видит её в коде: текст совпал, объект в момент `t` стоит на новом месте, размер стал новым. Вноси правку точно. Если перенести её иначе, человек увидит сдвиг дважды: из кода и поверх кода.

## Если ты агент в папке

- Ролик это HTML-файл, копия `Плеер.html`. Если его ещё нет, скопируй `Плеер.html` под новым именем, например `Ролик.html`
- Готовые стили и приёмы с кодом лежат в `Приёмы движения.html`. Код каждого в блоке `<script type="text/plain">`, рядом его название, правила и как его просят словами. Если просят стиль или приём по названию, бери код оттуда
- Код сцен лежит в этом файле в блоке `<script type="text/plain" id="reel-scenes">`. Меняй только этот блок. Код плеера ниже не трогай
- Отметки `//// ...` делят код на части, каждая часть выполняется отдельно. Если частей несколько, можно собрать их в одну, кроме `//// длительности из плеера`: её оставь отдельной и последней
- Не пиши `</script>` внутри кода сцен. Если нужно, пиши `<\/script>`
- Плеер может быть связан с этим файлом и сам записывать в него часть `//// длительности из плеера`. Поэтому перед каждой правкой перечитывай файл, а не правь по памяти. Плеер сам покажет человеку твою правку, просить его обновить страницу не нужно
- Человек присылает запросы из кнопки «Для ИИ»: название сцены, момент в секундах от начала сцены и что поправить. Если сцена растянута в плеере, в запросе есть `t` в коде сцены, ориентируйся на него. Блок `ПРАВКИ ИЗ ПЛЕЕРА` в запросе читай по разделу «Правки из плеера». В консоли его же отдаёт `reelPlayer.edits()`
- Проверка. Открой файл в браузере. В консоли есть `reelPlayer`: `reelPlayer.seek(2.5)` ставит кадр на 2,5 с, `reelPlayer.scenes` показывает сцены и ошибки. Посмотри скриншоты на нескольких секундах каждой сцены
- Ссылка `Ролик.html#t=2.5` открывает ролик сразу на 2,5 с, а `Ролик.html#t=2.5&clean` показывает только кадр на всё окно, без панели плеера. При окне 1920×1080 кадр снимается один к одному. Снимок в безголовом Chrome на Mac:

```
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --window-size=1920,1080 --virtual-time-budget=3000 --screenshot="кадр_2.5.png" "file:///полный/путь/к/Ролик.html#t=2.5&clean"
```

На Windows Chrome обычно лежит в `C:\Program Files\Google\Chrome\Application\chrome.exe`. Для вертикального ролика окно 1080×1920

## Проверка перед ответом

- Один блок кода, внутри только `reel` и `scene` и вспомогательные функции
- У каждой сцены есть `name` и `dur`, названия не повторяются
- `draw` зависит только от `t`, в коде нет ничего из списка «Нельзя»
- Цвета и шрифт через `var(--...)`
- Если задан темп музыки, склейки стоят на долях. При 120 ударах в минуту доля 0,5 с, такт 2 с. Длительность из задания ориентир: если она не делится на доли, возьми ближайшую подходящую и скажи об этом одной фразой
- Текст и графика не заходят в отступ 96 px от краёв кадра
- Если были правки из плеера, каждая внесена точно: текст как в «стало», объект в момент `t` на новом месте, выравнивание соблюдено
